# Reproduce the SARLA versus MCMC benchmark

## JAX NUTS baseline

Run `python nuts_benchmark.py /path/to/completed/original/benchmark`, then `python export_nuts.py /path/to/completed/original/benchmark`. NumPyro 0.21.0 runs 32 vectorized random-prior chains, 512 warm-up steps and 1,536 production steps per chain, for seeds 3, 17 and 41. It uses a dense adapted mass matrix, target acceptance 0.9 and maximum tree depth 10. A logistic transform with its exact Jacobian preserves the original bounded uniform prior. No optimizer or Hessian is used. The driver verifies the transformed potential against the original likelihood. Cold-start times include compilation in both warm-up and production, with device synchronization; JAX caches are cleared before each run. Leapfrog counts, divergences, ESS and R-hat are saved in `nuts-results.json`. The NUTS budget is not matched to the earlier methods; do not interpret the table as a controlled speed comparison. Raw samples and warm-up states are saved in the benchmark's `nuts` directory.

The “Before MCMC” view renders the saved final atlas mixture as a density cloud beside the numerical reference. Run `python export_atlas_cloud.py` after the replay exporters to regenerate this view. It uses direct independent mixture draws conditioned on the prior bounds, not an MCMC walk. Component weights, variance caps, and the broad Student-t tail follow the original engine. Density colors are normalized separately in the two panels (the atlas peak is estimated). Displayed mismatch values come from the original saved density-grid scoring. The `#atlas` link opens this view directly.

The current page gives SARLA 16 random interior-prior seeds, then uses JAX-assisted Gauss–Newton optimization to find good fits before building Hessian charts. Both gradient-free MCMC baselines start from 64 independent uniform prior draws and use a NumPy target with no optimization or derivatives. The measured Brandt2010 example uses four or the first two observations. The current protocol is in ../random-start-report.html; ../report.html preserves the earlier optimized-start experiment.

1. Create a Python 3.12 environment and install `requirements.txt`.
2. Save the unmodified [pinned SARLA2 engine](https://raw.githubusercontent.com/sudshu/sarla-autoresearch/842e93785f2fc9220869e371a9d937a202922eee/code/sarla2.py) as `upstream/code/sarla2.py` beside `benchmark.py`.
3. Set `OPENBLAS_NUM_THREADS=1` and `OMP_NUM_THREADS=1`.
4. Run `python benchmark.py`. This writes reference arrays, raw chain states, and `results/results.json`.
5. Run `python analyze.py` and `python make_report.py` to generate the figures, summary, standalone report, and complete source/data ZIP.
6. Optionally run `python export_replay.py . replay.json` to rebuild the compact replay data.
7. Run `python random_start_mcmc.py .` to generate new MCMC runs from independent prior draws. This driver does not import JAX. It writes `random-start/results.json`, `random-start/benchmark-results.csv`, and raw samples, preserving the original results.
8. Run `python export_random_replay.py . --update-page` to record actual Gauss–Newton iterates, verify endpoints against the retained SARLA starts, compare NumPy and JAX likelihoods numerically, and embed the new replay into ../index.html. Keep the supplied `replay-optimized.json` beside the exporter; it contains the verified original SARLA chart/sampling replay.
9. Copy `random-start/benchmark-results.csv` to `random-start-results.csv`, then run `python make_random_report.py` to regenerate ../random-start-report.html from `random-start-results.json`.

`random-start-results.json` and `random-start-results.csv` describe the current comparison. `results.json` and `benchmark-results.csv` preserve the earlier experiment. Sampling seeds are 3, 17, 41. SARLA retains the same single optimization seed (1729) across sampling runs; discovery reliability across independent optimization restarts is not measured. The tighter flag threshold (2 instead of 5) was chosen after the seed-3 pilot and checked with two further seeds. This small benchmark does not establish general speedup or convergence.

The interactive page embeds its replay data and can be downloaded to run offline. Initialization shows the 16 actual SARLA optimization paths and MCMC warm-up from independent prior draws. Production shows seed 3, 32 of 64 chains, 96 times after warm-up. Each path/phase is normalized independently for playback; playback is not elapsed time. Display thinning is independent of full-resolution scoring. Chart outlines are proposal components, not credible regions.

SARLA CPU totals include its recorded JAX setup, fitting, atlas construction, and MH production. MCMC totals include random initialization, warm-up, and production with NumPy. SARLA timings are retained from the earlier runs while MCMC was rerun, so these are descriptive measurements, not a controlled speedup experiment. Target-evaluation budgets are about 131,000, with extra residual/Jacobian/gradient/Hessian calls for SARLA reported separately. The original common setup routine compiled multiple batch shapes; its recorded time is retained in the setup accounting.

`export_replay.py` is the page's replay exporter. It accepts a completed benchmark directory and a JSON output path; it also expects `deliverables/summary.json` from the accompanying benchmark analysis. Its audit observer records chart geometry without editing upstream source or consuming random numbers and validates the replay against original chart centers and audit histories.
